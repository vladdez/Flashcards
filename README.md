# Flashcards

Приложение для интервального повторения: React + TypeScript + Vite, IndexedDB/Dexie, `ts-fsrs`, PWA и подключаемая синхронизация OneDrive.

**Адрес публикации:** https://vladdez.github.io/Flashcards/  
**Репозиторий:** https://github.com/vladdez/Flashcards

При начале работы папка `Cards` содержала только `CODEX_SPEC.md`, а удалённый репозиторий `vladdez/Flashcards` был пуст. Существующие страницы не заменялись. Оригинальная спецификация сохранена без изменений.

## Запуск и проверки

Нужен Node.js **24 LTS** (минимум 22.12).

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173/. Приложение работает без Microsoft-аккаунта и без сервера данных.

```sh
npm run lint
npm run typecheck
npm test
VITE_BASE_PATH=/Flashcards/ npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright запускает production preview на http://127.0.0.1:4173/Flashcards/. Перед E2E обязательно соберите с указанным base. На компьютере с установленным Google Chrome можно выполнить `PW_CHROME=1 npm run test:e2e`. Тестовые профили браузера изолированы от пользовательских данных. Скриншоты и трассировки остаются в игнорируемой папке `test-results/`.

Для обычного production preview:

```sh
VITE_BASE_PATH=/Flashcards/ npm run build
VITE_BASE_PATH=/Flashcards/ npm run preview
```

## Что умеет приложение

- Библиотека, вложенные папки с защитой от циклов, поиск по колодам и словам. Последняя **изученная** колода закрепляется сверху, включая вложенные папки.
- Создание, переименование, перемещение и удаление папок и колод; язык, ручной флаг, направления, дневной лимит. При удалении папки содержимое переходит на уровень выше.
- Редактор слова, перевода, примеров, заметок и тегов; перенос карточки между колодами. Карандаш во время обучения сохраняет текущую карточку и прогресс.
- Реальный FSRS с retention 90%, независимыми расписаниями `forward`/`reverse` и четырьмя рассчитанными оценками. По умолчанию 80 новых **уникальных слов** в день. Слово с ответом хотя бы в одном направлении уже введено; другое направление не расходует лимит повторно. Лимит 0 не блокирует ранее введённые слова и повторения.
- Критерий выученности: `scheduled_days >= 21` в каждом активном направлении. Выученные слова остаются в очереди повторений. Редактирование текста и смена режима не сбрасывают историю. Сброс — отдельная подтверждаемая команда.
- Серия дней и рекорд по фактическим ответам, семь последних календарных дней, общая статистика. Часовой пояс меняется в настройках; до конца сегодняшнего дня серия за вчера сохраняется.
- Светлая, тёмная и системная темы. Клавиши: пробел — ответ, 1–4 — оценка после переворота. Примеры всегда открываются вместе с ответом, курсивом.
- Локальные атомарные записи, восстановление после перезагрузки, PWA, подтверждение обновления без удаления IndexedDB.

## Импорт, экспорт и резервные копии

**Импорт колоды:** файл создаёт одну новую колоду с редактируемым именем файла и выбранной папкой. **Импорт карточек:** добавляет строки в существующую колоду. Для новой колоды переключитесь на первый режим.

Примеры доступны в интерфейсе и в `public/examples/german.csv`, `public/examples/german.xlsx`. Это синтетические примеры, не пользовательские данные.

- CSV: UTF-8, BOM, `,`, `;`, tab, кавычки и многострочные ячейки; TSV можно вставить в текстовое поле.
- XLSX: читается **первый лист**. Заголовки в первой непустой строке. `.xls` не поддерживается.
- Автоматическое и ручное сопоставление колонок. Минимум слово и перевод; примеры можно выбрать из нескольких колонок (`example`, `example_1`, `example_2`, `пример`, `Beispiel`). В одной ячейке примеры разделяются переносами строк. Не используйте `|` как разделитель примеров — он сохраняется как текст.
- Строки без слова или перевода обозначаются и пропускаются. Ошибки синтаксиса CSV блокируют фиксацию; пользователь должен исправить файл. Ограничение: 10 МБ и 20 000 строк за импорт.
- Дубликаты определяются внутри целевой колоды и текущего файла: NFC, trim, свёртка пробелов, сравнение без регистра. Для каждой строки требуется выбор **пропустить / обновить / добавить отдельную**, есть массовый выбор. При обновлении сохраняются ID, история и объединение прежних и новых примеров. Для удаления старого примера используйте редактор карточки.
- Фиксация всего импорта атомарна. Если колода изменилась после предпросмотра, операция отменяется и требуется перепроверка. При нескольких одноимённых карточках обновляется одна определённая существующая карточка; чтобы выбрать конкретную, используйте редактор.
- CSV/XLSX содержат слова, переводы и примеры. CSV защищён от исполнения формул при открытии в таблицах; специальные начальные символы могут получить защитный апостроф. XLSX записывает текстовые ячейки.
- **Полный JSON** содержит версии схемы, папки, колоды, карточки, расписания, настройки, логи и исходные операции. Перед восстановлением проверяются типы, UUID, ссылки, история и соответствие производного состояния журналу. Восстановление объединяет данные без удаления текущих; повторный импорт идемпотентен. Перед объединением интерфейс скачивает копию текущей библиотеки. Для восстановления на новом устройстве откройте приложение и импортируйте JSON. Максимум 100 МБ.

## Подключение OneDrive

Реальные логин и синхронизация требуют **вашей регистрации Microsoft Entra SPA**. Client ID — публичный идентификатор, не секрет. Client secret не нужен и не должен добавляться в приложение.

1. Откройте [Microsoft Entra admin center](https://entra.microsoft.com/) → App registrations → New registration.
2. Для личных и рабочих аккаунтов выберите _Accounts in any organizational directory and personal Microsoft accounts_. Для ограниченного корпоративного приложения укажите подходящий tenant authority.
3. Authentication → Add a platform → **Single-page application (SPA)**. Добавьте точные redirect URI:
   - `http://localhost:5173/auth.html` — разработка, открытая именно через localhost;
   - `http://127.0.0.1:5173/auth.html` — если политика регистрации допускает этот loopback URI;
   - `https://vladdez.github.io/Flashcards/auth.html` — GitHub Pages.
4. API permissions → Microsoft Graph → **Delegated permissions** → `Files.ReadWrite.AppFolder`. В организации администратор может запретить пользовательское consent или потребовать одобрение. Приложение не расширяет разрешения до всей файловой системы.
5. Скопируйте Application (client) ID. В GitHub: Settings → Secrets and variables → Actions → **Variables**:
   - `VITE_MS_CLIENT_ID`: ваш UUID;
   - `VITE_MS_AUTHORITY`: `https://login.microsoftonline.com/common` (необязательно; это default);
   - `VITE_MS_REDIRECT_URI`: `https://vladdez.github.io/Flashcards/auth.html` (необязательно, если автоматически вычисленный URI совпадает).
6. Запустите workflow **Check and deploy Flashcards** заново. `VITE_`-параметры встраиваются при сборке; изменение Variables без новой сборки не меняет сайт.
7. В приложении: Настройки → Подключить OneDrive → вход → сравнение данных → **Объединить и включить синхронизацию**. Повторите на втором устройстве с той же Entra-регистрацией и тем же Microsoft-аккаунтом.

Локально скопируйте `.env.example` в `.env.local` и заполните параметры. `.env.local` игнорируется Git. Для localhost задайте соответствующий URI явно, если открываете приложение по другому hostname.

MSAL Browser **5.25.0** использует отдельную страницу `auth.html` с официальным `@azure/msal-browser/redirect-bridge`; это учтено в многостраничной сборке. OAuth authorization code + PKCE выполняет MSAL. Токены управляются MSAL в браузере, не включаются в резервные копии и никогда не попадают в репозиторий. Разрешите popup для сайта. Сбой/истечение сессии не блокирует обучение: повторно нажмите «Подключить OneDrive».

### Как защищены данные при синхронизации

- `operations` в IndexedDB — долговечный журнал и очередь. Редактирование и обновление локального представления коммитятся одной Dexie-транзакцией. UUID операций не меняются при повторах.
- В облаке **нет перезаписываемого снимка всей базы или общего изменяемого индекса**. Приложение записывает неизменяемые пакеты `fc1-<UUID>.json` максимум по 100 операций в `/me/drive/special/approot`.
- Пакеты загружаются через Graph upload session с `@microsoft.graph.conflictBehavior: fail`, чанками по 320 КиБ. При HTTP 409/412 существующее содержимое проверяется целиком; совпадающий пакет считается доставленным, отличающийся не перезаписывается. Потеря подтверждения безопасно переживает повторную отправку.
- Список файлов обходится с пагинацией; ETag используется, чтобы не скачивать неизменившиеся файлы. Новые пакеты сначала валидируются и объединяются, и только затем отмечаются прочитанными. Если набор пакетов временно неполон, никакое частичное состояние не применяется; следующая синхронизация повторит чтение.
- Поля редактирования имеют причинные ссылки на предыдущие операции. Независимые поля объединяются автоматически; параллельные изменения одного поля хранят обе версии, показываются в настройках и разрешаются новой причинно связанной операцией. До выбора видна детерминированная версия, но альтернативы остаются в журнале. Удаления представлены tombstones, история сохраняется.
- Ответы — неизменяемые события. Состояние FSRS воспроизводится в порядке `(reviewedAt, id)`, с retention каждого ответа, зафиксированной версией алгоритма и отключённым fuzz. Ответы обоих устройств сохраняются, даже если они оценили одну карточку офлайн. Системные часы устройств должны быть корректны.
- Автосинхронизация запускается при открытии, изменении журнала (debounce 1,8 с), возвращении в онлайн, возврате во вкладку и каждые 60 с пока вкладка видима. Кнопка запускает тот же процесс вручную. Параллельные триггеры внутри вкладки объединяются; независимые вкладки используют идемпотентные пакеты.
- Первое подключение предлагает объединение с предварительным подсчётом. Разрушительной замены локальной/облачной базы нет. Для исключения локальных данных из другого аккаунта отмените подключение и используйте отдельный профиль браузера.
- При отключении MSAL-кэш очищается, локальная библиотека и данные в OneDrive остаются.

**Проверка на живом Microsoft-аккаунте обязательна после настройки.** Mock-тесты проверяют протокол, но не заменяют проверку consent, CORS, tenant policies и реального upload session. Проверьте изменения и ответы с двух устройств, работу без сети и повторный вход после истечения сессии.

## GitHub Pages

Workflow `.github/workflows/deploy.yml` выполняет `npm ci`, ESLint, TypeScript, Vitest, production build, Playwright desktop/mobile и публикацию только после успешных проверок.

В Settings → Pages → Build and deployment → Source выберите **GitHub Actions**. Push в `main` или ручной запуск Actions публикует:

**https://vladdez.github.io/Flashcards/**

Для отдельного домена установите build base `/`. Для интеграции в другой существующий сайт используйте `VITE_BASE_PATH=/REPO/flashcards/`, копируйте содержимое `dist` в `flashcards/` внутри **общего** Pages-артефакта и сохраняйте остальные страницы. Не публикуйте только эту папку поверх артефакта существующего сайта. В этом репозитории до реализации сайта не было.

Маршруты используют hash (`#/deck/<id>`), поэтому обновление страницы не требует серверного fallback. Manifest, assets, `auth.html` и service worker учитывают base. Scope service worker ограничен приложением, пользовательский сайт на другом пути не перехватывается.

## Архитектура и версии

- `src/core/model.ts` — модели и проверка внешних данных Zod.
- `src/core/db.ts` — Dexie, миграции, атомарные действия, защита от двойного ответа.
- `src/core/merge.ts` — причинное объединение операций и конфликты.
- `src/core/study.ts` — адаптер `ts-fsrs`, очереди, прогресс, календарные серии.
- `src/core/import.ts`, `backup.ts` — импорт/экспорт и резервные копии.
- `src/sync/` — MSAL, Graph transport, синхронизация, автоматические триггеры.
- `src/pages/`, `src/components/` — экраны и доступные native-dialog редакторы.
- `tests/` — бизнес-логика, React Testing Library, mock Graph и E2E.

Точные версии закреплены в `package.json` и `package-lock.json`. FSRS **5.4.2** использует официальные `repeat` / `next` и полную сериализацию текущего `Card`, включая `learning_steps`. Не заменять версию FSRS без миграции/проверки воспроизведения исторических событий. Формат данных `schemaVersion: 1`; версия IndexedDB `2` добавляет индекс и пересоздаёт производное представление из журнала.

Актуальные XLSX API отличаются от старых примеров: `read-excel-file` **9.3.12** → `readSheet(file, 1)`, `write-excel-file` **4.1.1** → `writeXlsxFile(data).toFile(name)`.

Официальные справки: [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs), [OneDrive App Folder](https://learn.microsoft.com/en-us/graph/onedrive-sharepoint-appfolder), [Graph upload sessions](https://learn.microsoft.com/en-us/graph/api/driveitem-createuploadsession?view=graph-rest-1.0), [MSAL Browser](https://learn.microsoft.com/en-us/entra/msal/javascript/browser/about-msal-browser), [Dexie React](https://dexie.org/docs/Tutorial/React), [Vite Pages](https://vite.dev/guide/static-deploy.html), [Vite PWA](https://vite-pwa-org.netlify.app/).

## Ограничения первой версии

- PWA офлайн доступна после завершения первой загрузки кэша. Приложение предлагает обновление, а не перезагружает учебную сессию автоматически. Очистка данных сайта, приватный режим и ограничения iOS могут удалить IndexedDB; используйте резервную копию/синхронизацию.
- Закрытая iOS PWA не гарантирует фоновую синхронизацию. Перед переходом на другое устройство дождитесь статуса «Синхронизировано».
- Журнал и tombstones не обрезаются. Восстановление состояния пока повторно проигрывает историю; для очень больших коллекций и многолетних журналов потребуются проверенные checkpoints/компактация. Масштабирование до сотен тысяч ответов не заявляется.
- При изменении текста на двух устройствах нужен выбор версии. Автоматическое понимание смысла текстов не выполняется.
- Только первый лист XLSX, без вложенных файлов, изображений, аудио, Anki/ZIP, совместных аккаунтов и расширенных графиков — согласно границам спецификации.
- Пользовательские данные не отправляются в аналитику. Импортированный HTML отображается как текст React. Облако используется только после подключения OneDrive.
