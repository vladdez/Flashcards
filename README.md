# Flashcards

Приложение для интервального повторения: React + TypeScript + Vite, IndexedDB/Dexie, `ts-fsrs`, PWA и подключаемая синхронизация Supabase Auth + PostgreSQL.

**Адрес публикации:** https://vladdez.github.io/Flashcards/  
**Репозиторий:** https://github.com/vladdez/Flashcards

Это существующее приложение, облачный слой которого заменён на Supabase. По уточнению владельца от 2026-10-14 реальных пользовательских данных в прежнем облаке нет: перенос из OneDrive не требуется и не реализуется. Продуктовые требования описаны в `CODEX_SPEC.md`, актуальные границы замены облака — в `CODEX_MIGRATION_ONEDRIVE_TO_SUPABASE.md`.

## Запуск и проверки

Нужен Node.js **24 LTS** (минимум 22.12).

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173/. Приложение работает без аккаунта и без настроенного сервера данных.

```sh
npm run lint
npm run typecheck
npm test
VITE_BASE_PATH=/Flashcards/ npm run build
npx playwright install chromium
npm run test:e2e
```

Playwright запускает production preview на http://127.0.0.1:4173/Flashcards/. Перед E2E обязательно соберите с указанным base. На компьютере с установленным Google Chrome можно выполнить `PW_CHROME=1 npm run test:e2e`. Тестовые профили браузера изолированы от пользовательских данных. Скриншоты и трассировки остаются в игнорируемой папке `test-results/`.

Для обычного production preview:

```sh
VITE_BASE_PATH=/Flashcards/ npm run build
VITE_BASE_PATH=/Flashcards/ npm run preview
```

## Что умеет приложение

- Библиотека, вложенные папки с защитой от циклов, поиск по колодам и словам. Последняя **изученная** колода закрепляется сверху и остаётся видимой внутри своей папки, в том числе вложенной.
- Создание, переименование, перемещение и удаление папок и колод; язык, ручной флаг, направления, дневной лимит. При удалении папки содержимое переходит на уровень выше.
- Редактор слова, перевода, примеров, заметок и тегов; перенос карточки между колодами. Карандаш во время обучения сохраняет текущую карточку и прогресс.
- Реальный FSRS с retention 90%, независимыми расписаниями `forward`/`reverse` и четырьмя рассчитанными оценками. По умолчанию 80 новых **уникальных слов** в день. Слово с ответом хотя бы в одном направлении уже введено; другое направление не расходует лимит повторно. Лимит 0 не блокирует ранее введённые слова и повторения.
- Первый учебный шаг **«Хорошо» — 30 минут**. При retention 90% новая карточка предлагает «Снова» 1 мин, «Трудно» 6 мин, «Хорошо» 30 мин, «Легко» 8 дней. Последующие интервалы рассчитывает FSRS; после забывания на этапе повторений остаётся шаг 10 минут. Обновление IndexedDB до v5 пересчитывает существующие расписания по тем же новым правилам. Изменений Supabase не требуется; для одинаковых расписаний обновите приложение на всех устройствах.
- Критерий выученности: `scheduled_days >= 3` в каждом активном направлении. Выученные слова остаются в очереди повторений. Редактирование текста и смена режима не сбрасывают историю. Сброс — отдельная подтверждаемая команда.
- Серия дней и рекорд по фактическим ответам, семь последних календарных дней, общая статистика. Часовой пояс меняется в настройках; до конца сегодняшнего дня серия за вчера сохраняется.
- Светлая, тёмная и системная темы. Клавиши: пробел — ответ, 1–4 — оценка после переворота. Примеры всегда открываются вместе с ответом, курсивом.
- Локальные атомарные записи, восстановление после перезагрузки, PWA, подтверждение обновления без удаления IndexedDB.

## Импорт, экспорт и резервные копии

**Импорт колоды:** файл создаёт одну новую колоду с редактируемым именем файла и выбранной папкой. **Импорт карточек:** добавляет строки в существующую колоду. Для новой колоды переключитесь на первый режим.

Примеры доступны в интерфейсе и в `public/examples/german.csv`, `public/examples/german.xlsx`. Это синтетические примеры, не пользовательские данные.

- CSV: UTF-8, BOM, `,`, `;`, tab, кавычки и многострочные ячейки; TSV можно вставить в текстовое поле.
- XLSX: читается **первый лист**. Заголовки в первой непустой строке. `.xls` не поддерживается.
- Автоматическое и ручное сопоставление колонок. Минимум слово и перевод; примеры можно выбрать из нескольких колонок (`example`, `example_1`, `example_2`, `пример`, `Beispiel`). В одной ячейке примеры разделяются переносами строк. Не используйте `|` как разделитель примеров — он сохраняется как текст.
- Строки без слова или перевода обозначаются и пропускаются. Ошибки синтаксиса CSV блокируют фиксацию; пользователь должен исправить файл. Ограничение: 10 МБ и 20 000 строк за импорт.
- Дубликаты определяются внутри целевой колоды и текущего файла: NFC, trim, свёртка пробелов, сравнение без регистра. Повторные строки выделены красным и меткой **«Дубликат»** рядом со словом. Для каждой строки требуется выбор **объединить / пропустить / обновить / добавить отдельную**. Кнопки **«Объединить все дубликаты»** и **«Добавить все, включая дубликаты»** выбирают действие сразу для всех совпадений; запись происходит после нажатия «Импортировать».
- **Объединить** сохраняет первоначальное слово, все различные строки перевода и примеры в одной карточке. Одинаковые строки не повторяются; регистр переводов сохраняется (например, `US` и `us` — разные значения). **Обновить** заменяет перевод и дополняет примеры. Оба действия сохраняют ID и историю FSRS в обоих направлениях. Для удаления старого примера используйте редактор карточки.
- Фиксация всего импорта атомарна. Если колода изменилась после предпросмотра, операция отменяется и требуется перепроверка. При нескольких одноимённых карточках обновляется или дополняется одна определённая существующая карточка; другие ранее сохранённые карточки не удаляются. Чтобы выбрать конкретную, используйте редактор.
- CSV/XLSX содержат слова, переводы и примеры. CSV защищён от исполнения формул при открытии в таблицах; специальные начальные символы могут получить защитный апостроф. XLSX записывает текстовые ячейки.
- **Полный JSON** содержит версии схемы, папки, колоды, карточки, расписания, настройки, логи и исходные операции. Перед восстановлением проверяются типы, UUID, ссылки, история и соответствие производного состояния журналу. Восстановление объединяет данные без удаления текущих; повторный импорт идемпотентен. Перед объединением интерфейс скачивает копию текущей библиотеки. Для восстановления на новом устройстве откройте приложение и импортируйте JSON. Максимум 100 МБ.

## Подключение Supabase

Используется существующий проект **`lwcmazbqwbhfumjbbzcj`**, URL `https://lwcmazbqwbhfumjbbzcj.supabase.co`. Приложение работает локально, если публичная конфигурация отсутствует. Microsoft Entra, Graph и MSAL больше не используются. **[Пошаговая установка через SQL Editor и настройка входа](docs/SUPABASE_SETUP.md)** содержит готовые файлы, ожидаемый результат проверки и проверку на двух устройствах.

1. В Supabase Dashboard → SQL Editor примените **`supabase/migrations/202610130001_supabase_sync.sql`** целиком, один раз, затем выполните **`supabase/verify_installation.sql`** и получите `OK`. Это создаёт схему с нуля и проверяет права, не импортируя старые облачные данные. Альтернатива: Supabase CLI, `supabase link --project-ref lwcmazbqwbhfumjbbzcj`, затем сначала `supabase db push --dry-run`; сверяйте историю миграций существующего проекта перед `db push`.
2. Authentication → Sign In / Providers → Email: включите email-вход; разрешите регистрацию новых пользователей либо заранее пригласите нужных пользователей. Настройте **свой SMTP** для отправки писем обычным пользователям: встроенный отправитель Supabase ограничен разрешёнными адресами и лимитами.
3. Authentication → URL Configuration:
   - **Site URL:** `https://vladdez.github.io/Flashcards/`
   - **Redirect URLs:** `https://vladdez.github.io/Flashcards/`, `http://localhost:5173/`, `http://127.0.0.1:5173/`, `http://127.0.0.1:4173/Flashcards/`.
   - Если dev запускается с base `/Flashcards/`, добавьте также `http://127.0.0.1:5173/Flashcards/`. URL должен точно совпадать с адресом приложения. Для production не используйте wildcard.
4. В шаблоне **Magic Link** оставьте `{{ .ConfirmationURL }}`. Для входа кодом добавьте `{{ .Token }}`. Например: `<p><a href="{{ .ConfirmationURL }}">Войти</a></p><p>Код: {{ .Token }}</p>`. На iPhone/PWA скопируйте адрес кнопки входа из **нового** письма в **Настройки → Ссылка из письма → Войти по ссылке**. Это работает со стандартным шаблоном без цифрового кода и сохраняет сессию в текущем приложении. Прямой переход по magic link с PKCE требует того же браузера, где запросили письмо. После входа подтвердите **Сравнить и объединить данные** на обоих устройствах с одним email. Callback идёт на корень приложения, затем на `#/settings`; `auth.html` больше не нужен.
5. Settings → API Keys: возьмите **Publishable key** (`sb_publishable_…`). В GitHub → Settings → Secrets and variables → Actions → **Variables** задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`. Это публичные параметры, они встраиваются в frontend. **Secret key, service_role, пароль БД и management token запрещены в Vite/Git.** Сборка отклоняет ключи другого типа.
6. Локально скопируйте `.env.example` в игнорируемый `.env.local` и заполните публичные параметры. Для сборки Pages задайте `VITE_BASE_PATH=/Flashcards/`. Изменение Variables требует новой сборки. PR только проверяется; публикация происходит из `main` после проверки и ручного слияния.
7. В приложении: Настройки → email → письмо/код → **Скачать копию перед подключением** → **Сравнить и объединить данные** → проверьте аккаунт и числа → подтвердите объединение. Вход сам по себе не разрешает отправку локальных карточек. Повторите на втором устройстве с тем же email.

Сессия автоматически восстанавливается и обновляется Supabase SDK. Выход останавливает синхронизацию в остальных вкладках этого браузера и сохраняет локальные данные. **Локальная библиотека остаётся доступной после выхода**; для общего компьютера используйте отдельные профили ОС/браузера. После первого подтверждения библиотека привязана к проекту и UUID аккаунта. Вход в другой аккаунт блокирует облачную передачу; для другой библиотеки нужен отдельный профиль. Намеренный перенос выполняется через JSON-копию в отдельном профиле.

### Как защищены данные

- Имя IndexedDB — **`flashcards-v1`**. Версия `4` удаляет неиспользуемый кэш `batches` и метаданные прежнего транспорта (`syncAccount`, `lastSync`, `seen:*`). Журнал `operations`, снимок `state`, настройки и состояние Supabase сохраняются. Формат резервной копии — `schemaVersion: 1`.
- Локальные редактирования и ответы сначала атомарно коммитятся в IndexedDB. Журнал операций — долговечная очередь, квитанции Supabase учитываются отдельно по проекту/пользователю.
- PostgreSQL хранит **неизменяемые операции**, а не перезаписываемый снимок. `flashcards_push` проверяет существующий UUID: одинаковое содержимое подтверждает повтор, отличающееся отклоняет всю транзакцию. Удаление записывается tombstone. Идентификаторы старых операций/ответов не меняются.
- Причинные родители и ссылки папка → колода → карточка → ответ защищены составными foreign keys с `owner_id`. Все таблицы закрыты RLS для чужих пользователей, анонимам нет доступа. Клиент не передаёт owner в RPC: сервер берёт его из `auth.uid()`. Прямые UPDATE/DELETE/INSERT журнала запрещены; запись проходит через проверяемую функцию с фиксированным `search_path`.
- `flashcards_folders`, `flashcards_decks`, `flashcards_cards`, `flashcards_user_settings` — RLS-safe представления полных историй. `flashcards_review_logs` и `flashcards_schedule_events` моделируют неизменяемые ответы и события **по каждому направлению**. Расписание воспроизводит существующий `ts-fsrs 5.4.2` на клиенте; SQL не заменяет FSRS и не выбирает последний снимок. Подробнее: [решение об архитектуре](docs/SUPABASE_MIGRATION.md).
- Конкурирующие текстовые изменения и удаления сохраняют обе версии; существующий интерфейс конфликтов остался. FSRS воспроизводит все события в прежнем порядке `(reviewedAt, id)`, с retention каждого ответа и без fuzz. Нужны корректные часы устройств.
- Сервер присваивает ревизии **под блокировкой строки пользователя**, поэтому курсор не пропускает поздно завершившиеся транзакции. Загрузка читает фиксированную границу с пагинацией. Проверка, объединение, квитанции и курсор коммитятся одной IndexedDB-транзакцией. Неполная/повреждённая история не заменяет локальную базу.
- Автосинхронизация: открытие, локальные изменения (1,8 с), online, возвращение во вкладку и каждые 60 с видимой вкладки. После сбоя следующий триггер безопасно повторяет отправку. Закрытая iOS PWA не гарантирует фоновую работу. Realtime не требуется.
- Токены находятся только в хранилище Supabase Auth браузера; резервные копии содержат только учебные данные. Смена сессии отменяет старую синхронизацию, а HTTP-запросы привязаны к подтверждённому UUID.

### Проверки и применение схемы

`npm test` включает настоящие SQL/RLS-тесты на **PGlite (PostgreSQL WASM)** с двумя пользователями и ролью anon, проверку SQL-диагностики установки, обновления IndexedDB v2/v3/v4 → v5 с пересчётом учебного шага, резервных копий, а также mock-тесты auth/HTTP/синхронизации. Playwright проверяет существующие импорт/обучение/PWA и два независимых браузера с перехваченным Supabase HTTP. Эти проверки **не являются живым входом в Supabase**. Если сборка без облачной конфигурации, два auth-сценария на каждом viewport явно пропускаются, остальные E2E продолжают проверять офлайн-приложение.

Для включения облака выполните [проверку на настоящем проекте и двух устройствах](docs/SUPABASE_SETUP.md#5-проверить-на-двух-устройствах). Используйте новые тестовые карточки: проверка переноса пользовательской истории не требуется. В PR отдельно отмечайте применение SQL, SMTP/redirects и результаты живой синхронизации; зелёные mock-тесты не доказывают настройку размещённого сервера.

В Settings → Pages → Build and deployment → Source выберите **GitHub Actions**. Push в `main` или ручной запуск Actions публикует:

**https://vladdez.github.io/Flashcards/**

Для отдельного домена установите build base `/`. Для интеграции в другой существующий сайт используйте `VITE_BASE_PATH=/REPO/flashcards/`, копируйте содержимое `dist` в `flashcards/` внутри **общего** Pages-артефакта и сохраняйте остальные страницы. Не публикуйте только эту папку поверх артефакта существующего сайта. В этом репозитории до реализации сайта не было.

Маршруты используют hash (`#/deck/<id>`), поэтому обновление страницы не требует серверного fallback. Manifest, assets и service worker учитывают base. Scope service worker ограничен приложением, пользовательский сайт на другом пути не перехватывается.

## Архитектура и версии

- `src/core/model.ts` — модели и проверка внешних данных Zod.
- `src/core/db.ts` — Dexie, миграции, атомарные действия, защита от двойного ответа.
- `src/core/merge.ts` — причинное объединение операций и конфликты.
- `src/core/study.ts` — адаптер `ts-fsrs`, очереди, прогресс, календарные серии.
- `src/core/import.ts`, `backup.ts` — импорт/экспорт и резервные копии.
- `src/sync/` — Supabase Auth, RPC transport, синхронизация и автоматические триггеры.
- `src/pages/`, `src/components/` — экраны и доступные native-dialog редакторы.
- `supabase/migrations/` — PostgreSQL, RLS, серверные RPC и неизменяемый журнал.
- `tests/` — бизнес-логика, React Testing Library, PGlite RLS, mock Supabase и E2E.

Точные версии закреплены в `package.json` и `package-lock.json`. FSRS **5.4.2** использует официальные `repeat` / `next` и полную сериализацию текущего `Card`, включая `learning_steps`. Не заменять версию FSRS без проверки воспроизведения событий. Формат данных `schemaVersion: 1`; версия IndexedDB `2` добавляла индекс, `3` — квитанции Supabase, `4` убирает неиспользуемый кэш прежнего транспорта. Схема FSRS не менялась.

Актуальные XLSX API отличаются от старых примеров: `read-excel-file` **9.3.12** → `readSheet(file, 1)`, `write-excel-file` **4.1.1** → `writeXlsxFile(data).toFile(name)`.

Официальные справки: [ts-fsrs](https://github.com/open-spaced-repetition/ts-fsrs), [Supabase Email Auth](https://supabase.com/docs/guides/auth/auth-email-passwordless), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Auth Redirects](https://supabase.com/docs/guides/auth/redirect-urls), [Dexie React](https://dexie.org/docs/Tutorial/React), [Vite Pages](https://vite.dev/guide/static-deploy.html), [Vite PWA](https://vite-pwa-org.netlify.app/).

## Ограничения первой версии

- PWA офлайн доступна после завершения первой загрузки кэша. Приложение предлагает обновление, а не перезагружает учебную сессию автоматически. Очистка данных сайта, приватный режим и ограничения iOS могут удалить IndexedDB; используйте резервную копию/синхронизацию.
- Закрытая iOS PWA не гарантирует фоновую синхронизацию. Перед переходом на другое устройство дождитесь статуса «Синхронизировано».
- Журнал и tombstones не обрезаются. Восстановление состояния пока повторно проигрывает историю; для очень больших коллекций и многолетних журналов потребуются проверенные checkpoints/компактация. Масштабирование до сотен тысяч ответов не заявляется.
- При изменении текста на двух устройствах нужен выбор версии. Автоматическое понимание смысла текстов не выполняется.
- Только первый лист XLSX, без вложенных файлов, изображений, аудио, Anki/ZIP, совместных аккаунтов и расширенных графиков — согласно границам спецификации.
- Пользовательские данные не отправляются в аналитику. Импортированный HTML отображается как текст React. Облако используется только после входа и подтверждения объединения.
