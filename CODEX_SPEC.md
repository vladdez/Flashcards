# Техническое задание для Codex: приложение интервального повторения слов

**Рабочее название:** Flashcards.  
**Цель:** создать полностью работоспособное mobile-first веб-приложение/PWA с карточками и интервальными повторениями, доступное на GitHub Pages, с локальным офлайн-хранением и автоматической синхронизацией через OneDrive после подключения аккаунта.

## 0. Правила работы Codex

1. **Сначала проанализируй существующий репозиторий.** Если сайт уже есть, интегрируй приложение отдельным маршрутом `/flashcards/` либо самостоятельным изолированным подпроектом, не ломая существующие страницы. Если репозиторий пуст, создай приложение с нуля. Не удаляй и не перезаписывай пользовательские файлы без необходимости.
2. Работай поэтапно, но реализуй рабочую вертикаль end-to-end: просмотр колод → импорт → повторение → сохранение прогресса → перезагрузка → восстановление. Избегай заглушек, выдаваемых за готовые функции.
3. Все данные пользователя должны оставаться вне публичного Git-репозитория. Никогда не коммить секреты, access tokens, реальные колоды пользователя и содержимое OneDrive.
4. Используй актуальные стабильные версии библиотек и их официальные API. Если текущий API отличается от примеров, следуй официальной документации и зафиксируй решение в README.
5. Предпочитай читаемый TypeScript, типизированные модели, модульную структуру, автоматические тесты. Не реализуй собственную математику FSRS, если её предоставляет `ts-fsrs`.
6. После каждой существенной стадии запускай проверки. В конце предоставь: какие функции готовы, какие требуют пользовательской конфигурации, как запустить локально, как развернуть на GitHub Pages, какие тесты выполнены, известные ограничения.

## 1. Стек и архитектура

- **Frontend:** React + TypeScript + Vite; адаптивный интерфейс для iPhone, Android и компьютера.
- **Стили:** CSS variables / аккуратная дизайн-система; при необходимости Tailwind, если это не усложняет существующий проект.
- **Локальная база:** IndexedDB через Dexie; миграции схемы.
- **Алгоритм:** `ts-fsrs`; стандартные параметры FSRS, целевое запоминание **90%** по умолчанию; параметр меняется в настройках.
- **Импорт:** CSV (корректная обработка кавычек, запятых, точек с запятой, UTF-8) и XLSX (например, SheetJS или другая поддерживаемая библиотека). Поддержать также вставку таблицы TSV из буфера обмена, если несложно.
- **PWA:** `vite-plugin-pwa`, web manifest, иконки, корректный scope и service worker, доступность интерфейса и данных без сети после первой загрузки.
- **Облачная синхронизация:** адаптер Microsoft Graph/OneDrive, авторизация SPA через `@azure/msal-browser`, OAuth authorization code + PKCE, разрешение `Files.ReadWrite.AppFolder` (если поддерживается конкретным аккаунтом). Не создавать собственного сервера только ради логина.
- **Развёртывание:** GitHub Actions → GitHub Pages, корректная `base`-конфигурация Vite для пути репозитория или вложенного `/flashcards/`.
- **Тесты:** Vitest для бизнес-логики; React Testing Library для важных экранов; один или несколько end-to-end smoke-тестов (например, Playwright), если возможно.

**Архитектурный принцип:** local-first. Каждое действие сначала атомарно записывается в IndexedDB, интерфейс обновляется мгновенно, синхронизация происходит отдельно и не блокирует обучение.

## 2. Модели данных

Спроектируй типизированные сущности с устойчивыми UUID (не зависящими от названия):

- `Folder`: `id`, `parentId|null`, `name`, `icon?`, `sortOrder`, `createdAt`, `updatedAt`, `deletedAt?`.
- `Deck`: `id`, `folderId|null`, `name`, `languageCode?` (BCP-47), `flagEmoji` (пользовательский override), `flagIsManuallySet`, `studyMode` (`forward` | `reverse` | `both`), `newWordsPerDay` (по умолчанию 80), `lastStudiedAt?`, timestamps, tombstone.
- `Card`: `id`, `deckId`, `front` (слово/выражение), `back` (перевод), `examples` (массив строк, может быть пустым), `notes?`, `tags?`, timestamps, tombstone. Перевод и примеры должны быть отдельными полями, даже если рисуются рядом.
- `CardSchedule`: отдельная запись на пару `(cardId, direction)`, с сериализуемым FSRS-состоянием (due, stability, difficulty, elapsedDays, scheduledDays, reps, lapses, state, lastReview и поля, действительно необходимые выбранной версии `ts-fsrs`).
- `ReviewLog`: неизменяемые события с `id`, `cardId`, `direction`, `rating`, `reviewedAt` (UTC), `deviceId`, данными, достаточными для восстановления/проверки FSRS-состояния; не удалять историю при обычном редактировании карточки.
- `Settings`: целевая retention=0.90, настройки UI, локальная временная зона/обработка дат, sync metadata.
- `ChangeEvent`/`PendingSyncOperation`: устойчивые идентификаторы операций, версия схемы, id устройства, timestamp, тип действия, данные; tombstones для удалений.

Вводи версию схемы и миграции. Даты храни в UTC ISO 8601, показывай пользователю в локальном часовом поясе. Для streak используй календарный день в выбранной локальной зоне, а не «24 часа подряд». Предусмотри защиту от некорректных/дублированных данных при импорте и синхронизации.

## 3. Главная страница

- Наверху всегда выделена **последняя использованная колода** (по фактическому повторению), даже если она лежит глубоко в папке. Большая карточка «Продолжить», флаг, название, название папки, число повторений к сроку и прогресс.
- Ниже — дерево папок и остальные колоды. Папки можно создавать, переименовывать, перемещать и удалять с подтверждением. **По умолчанию поддержи вложенные папки** (пока это реализационное предположение, а не отдельно согласованная продуктовая функция); защита от циклов при перемещении. Колода принадлежит максимум одной папке.
- Каждая колода показывает: флаг/эмодзи, название, `выучено / всего`, процент/индикатор прогресса, количество карточек к повторению, при необходимости статус «Новые».
- Выученной считается карточка, для которой следующий интервал FSRS **не меньше 21 дня**. Если интервал вновь стал меньше 21 дня, статус возвращается в «В процессе». Карточки **продолжают повторяться**, даже если они «выучены».
- Если режим колоды `both`, слово засчитывается как выученное только при выполнении критерия **в обоих направлениях**. Для `forward`/`reverse` учитывается только активное направление. Процент — количество полностью выученных слов / количество уникальных карточек колоды.
- Пустые состояния, поиск колод/карточек, внятная мобильная навигация; последнюю колоду держи закреплённой в отдельном верхнем блоке, не дублируй её среди обычных карточек без необходимости.

## 4. Языки и флаги

- При создании колоды пользователь выбирает язык; автоматически подставляется разумный флаг: German → 🇩🇪, French → 🇫🇷, English → 🇬🇧 по умолчанию. Флаг — индикатор страны/варианта, поэтому пользователь **всегда может изменить его вручную** (например, English → 🇺🇸, 🇨🇦 или 🇦🇺).
- Сохраняй признак ручного выбора; не перезаписывай вручную выбранный флаг при последующих автоматических определениях.
- Для неязыковых колод можно выбрать эмодзи/значок, например 🧠.
- Язык карточек и направление задаются на уровне колоды; изменение языка не должно удалять прогресс.

## 5. Управление колодами и карточками

- Создать/переименовать/удалить колоду, поменять папку, язык, флаг, режим изучения; подтверждение удаления.
- Добавить карточку вручную, редактировать `front`, `back`, один или несколько примеров, необязательные теги/заметки; удалять/перемещать карточки.
- **Быстрое редактирование во время повторения:** значок карандаша открывает редактор (диалог/шторка), после сохранения пользователь возвращается к той же карточке.
- Обычная правка слова, перевода, примера не сбрасывает историю FSRS. Для существенного изменения смысла предусмотрите отдельную явную команду «Сбросить прогресс карточки» с подтверждением; никогда не делать это автоматически.
- Обеспечить уникальные ID и валидацию обязательных полей; изменения сохраняются локально сразу.

## 6. Импорт и экспорт

Два явных режима в интерфейсе:

**A. «Импорт карточек»** — файл CSV/XLSX или вставка TSV → пользователь выбирает существующую колоду либо создаёт новую.  
**B. «Импорт колоды»** — один CSV/XLSX файл = одна новая колода; имя по умолчанию берётся из имени файла и может редактироваться; пользователь выбирает папку назначения. Импорт нескольких отдельных файлов можно добавить, если без лишних рисков; импорт ZIP/Anki/Noji **не нужен в первой версии**.

Поля при импорте: минимум `word/front`, `translation/back`, `example` (необязательная отдельная колонка). Разреши ручное сопоставление колонок, покажи предпросмотр строк, ошибки, пропущенные строки, счётчики новых/дублированных карточек. Корректно работай с русским/немецким текстом, umlaut/ß, заголовками на разных языках, CSV с разделителями `,`, `;`, tab и экранированными кавычками. Несколько примеров могут поступать как отдельные колонки `example_1`, `example_2` либо единым полем; документируй принятый формат.

**Дубликаты:** находи совпадения **в целевой колоде** по нормализованной лицевой стороне (`Unicode NFC`, trim, сворачивание последовательных пробелов, регистронезависимое сравнение). Выделяй дубликаты в предпросмотре и требуй явного решения: **Пропустить / Обновить существующую / Добавить отдельную**; разреши отдельный выбор для каждой строки и «Применить ко всем». По умолчанию ничего не перезаписывать. При «Обновить» сохранять ID и прогресс старой карточки; существующие примеры не стирать без намерения пользователя. Сделай импорт атомарным (откат при ошибке/неполной операции), перед фиксацией чётко показывай последствия.

Экспорт: CSV/XLSX отдельной колоды для слов/переводов/примеров; отдельно **полная резервная копия** JSON с папками, колодами, карточками, FSRS-состояниями и логами, schemaVersion. Полная копия должна восстанавливаться с проверкой данных. Не выдавай CSV за резервную копию истории повторений.

## 7. Учебная карточка и управление сессией

**Лицевая сторона:** одно крупное слово/выражение по центру, минималистичный интерфейс, информация о колоде и прогрессе сессии. Тап/клик или кнопка «Показать ответ» переворачивает карточку.

**Обратная сторона:** исходное слово (или перевод при обратном режиме), правильный ответ; если у карточки есть примеры — **всегда показывать их сразу под ответом курсивом**, без дополнительного клика и без настройки скрытия. Если примеров нет — не оставлять пустого блока. В прямом и обратном направлении примеры остаются в ответной части. Кнопка быстрого редактирования доступна в сессии.

После раскрытия показать четыре большие цветные кнопки с рассчитанными интервалами под ними:

| Оценка | Цвет/пример токена | Значение |
|---|---|---|
| Снова / Again | светло-коралловый `#FBE5E5`, текст `#A13D43` | не смог вспомнить |
| Трудно / Hard | нежно-янтарный `#FFF0D4`, текст `#986316` | вспомнил с большим трудом |
| Хорошо / Good | мятный `#DEF3E7`, текст `#21694B` | нормально вспомнил |
| Легко / Easy | нежно-голубой `#E3ECFF`, текст `#385FA8` | сразу и без усилий |

Адаптируй цвета к тёмной теме; достаточный контраст, крупные touch targets (от 44×44 px), чёткие состояния нажатия и клавиатурная навигация. Интервалы **рассчитывай FSRS индивидуально для карточки**, не хардкодь «1 мин / 10 мин / 1 день / 4 дня» как реальные результаты. Учитывай учебные шаги начального обучения корректно с текущим API `ts-fsrs`. Показывай due- и new-сессии, не допуская случайного двойного начисления при быстрых нажатиях.

## 8. FSRS, направления и новые слова

- Используй `ts-fsrs` для preview вариантов и записи результата оценивания; параметры по умолчанию соответствуют **90% целевой retention**.
- Направления колоды: `forward` = иностранное слово → перевод, `reverse` = перевод → иностранное слово, `both` = оба варианта. **В `both` это две независимые учебные сущности:** разные расписания, история, due, оценки и прогресс. Не подменяй два расписания случайным чередованием одного.
- **Лимит новых слов:** редактируемый отдельно для каждой колоды; значение по умолчанию и помеченное как рекомендуемое — **80 уникальных слов в день**. Это продуктовый выбор пользователя, даже если нагрузка высокая. Значение 0 запрещает новые слова, но не запланированные повторения. Повторения не ограничиваются лимитом новых.
- В режиме `both` одна уникальная карточка/слово расходует единицу лимита новых слов, независимо от количества направлений. Если оба направления доступны, создавать независимые задания, не считать их двумя новыми словами.
- Новый день определяется локальным календарём. Сохраняй события просмотра/первого ввода для устойчивого учёта дневного лимита даже после перезагрузки.
- При изменении режима колоды сохраняй состояние всех направлений, не удаляй старую историю. При возврате в ранее выбранное направление используй его предыдущие данные.

## 9. Статистика и streaks

- На карточке колоды: количество выученных / всего, процент и due.
- На главной: **текущая серия дней** 🔥 и **рекордная серия** 🏆.
- Активный день = есть хотя бы один реально записанный ответ на карточку в любой колоде. Просмотр главной страницы или импорт не засчитываются. Учитывай локальные календарные даты. Текущая серия не должна «обрываться» с утра до окончания текущего дня: если вчера учились, а сегодня ещё нет, серия остаётся доступной для продолжения сегодня.
- Можно показать минимальный ряд из последних 7 дней. Расширенные графики/heatmap/геймификация **не входят в обязательный объём** до отдельного решения.

## 10. OneDrive: автоматическая синхронизация без потери данных

**Решение по продукту:** автоматическая облачная синхронизация + офлайн; **OneDrive — предпочтительный кандидат** (аккаунт личный или рабочий пока не уточнён). Реализуй подключаемый адаптер с рабочей авторизацией после настройки. Не выдавай интерфейс-заглушку за завершённую синхронизацию.

1. Используй Microsoft identity platform, `@azure/msal-browser` с PKCE, регистрацию SPA с разрешёнными redirect URI для localhost и GitHub Pages, конфигурация через `VITE_MS_CLIENT_ID` и другие несекретные переменные окружения. Никаких client secrets в браузере. Выбирай поддерживаемый authority для личных/рабочих аккаунтов и документируй ограничения администраторского consent.
2. Сохраняй данные только в **папку приложения** OneDrive (`/me/drive/special/approot` или эквивалент согласно текущим официальным Graph API), запрашивай минимально необходимые permissions `Files.ReadWrite.AppFolder`. Учитывай, что в некоторых организациях согласие ограничено.
3. Устройство продолжает работать полностью офлайн. Локальные изменения попадают в долговечную очередь и отправляются, когда авторизация и сеть доступны; при открытии приложения, возврате в онлайн и после локальных изменений. Не обещай гарантированной фоновой синхронизации при закрытой iOS PWA.
4. **Защита от конфликтов обязательна:** избегай last-write-wins перезаписи всей базы. Используй ревизии/eTag/`If-Match` там, где применимо, проверку изменений и повтор merge при конфликте. Для повторений применяй идемпотентные события с UUID и детерминированный порядок; никогда не теряй события ответа, сделанные на другом устройстве. При конкурентных изменениях одних и тех же текстовых полей покажи пользователю сравнение и выбор, если нельзя безопасно объединить; удаления — через tombstones.
5. Задай формат с `schemaVersion`, `deviceId`, operation IDs, временными метками, механизмами восстановления после частичного сбоя. Избегай бесконтрольной загрузки всего большого JSON-файла после каждого нажатия: пакетная отправка/дебаунс, инкрементальные события или эквивалентное надёжное решение. Если выбранная архитектура слишком сложна для первого PR, не имитируй синхронизацию — честно выдели её в отдельный готовый к реализации этап с тестируемым контрактом и работающим локальным MVP.
6. Статусы UI: «Не подключён», «Синхронизация», «Синхронизировано», «Офлайн / ожидает», «Конфликт», «Ошибка». Кнопки «Подключить OneDrive», «Синхронизировать сейчас», «Отключить» (при отключении локальные данные остаются). Покажи последнюю успешную синхронизацию.
7. **Первое подключение:** безопасно сравни локальную и облачную базы, не перезаписывай ни одну молча; предложи объединить либо явно выбрать восстановление из облака/локального устройства с резервной копией перед заменой.
8. Если OneDrive не настроен или недоступен, приложение не блокируется: оно полноценно работает локально с ручным экспортом полной резервной копии.

## 11. PWA и UX

- Русский язык интерфейса по умолчанию. Приоритет — читаемость, чистый современный дизайн, похожая логика взаимодействия с приложениями карточек, но **не копируй брендинг, логотипы и оригинальный дизайн Noji**.
- Светлая и тёмная темы с системной темой по умолчанию; приятная палитра кнопок, плавный flip без обязательных анимаций (`prefers-reduced-motion`).
- App manifest и иконки, работа в standalone-режиме, проверенные пути PWA на GitHub Pages; после первого онлайн-открытия доступны оболочка приложения и локальные данные офлайн.
- На мобильном: карточка и все четыре кнопки помещаются с разумной прокруткой, большие области нажатия, удобный импорт файлов через системный picker.
- На десктопе: клавиатурные действия для «Показать ответ» и выбора оценки, видимый focus, семантические кнопки, доступные диалоги. Не делай случайной отправки оценки до раскрытия ответа.
- Показывай ненавязчивые подтверждения сохранения, ошибки файлов, отмену опасных действий; не уничтожай данные при обновлении PWA.

## 12. Развёртывание и безопасность

- Добавь `.github/workflows/deploy.yml` с `npm ci`, lint/typecheck/tests/build и публикацией статического билда; если текущий проект уже имеет workflow, модифицируй минимально.
- Корректно настрой `base` для адреса вида `https://USER.github.io/REPO/flashcards/` или для отдельного поддомена. Не используй absolute-root ссылки, которые сломают поддиректорию.
- CSP и минимальные внешние зависимости по возможности, никакого исполнения импортированного HTML/JavaScript: отображай текст через безопасные React-компоненты, экранируй ввод.
- В README опиши регистрацию Microsoft Entra SPA, redirect URI и разрешения, локальную разработку, деплой, экспорт/восстановление и известные ограничения браузеров/iOS.
- Не отправляй пользовательские карточки на сторонние аналитические сервисы без явного разрешения.

## 13. Проверки и критерии приёмки

Реализуй и автоматизируй по возможности следующие сценарии:

1. Создание папки, вложенной папки и двух колод; перемещение колоды не меняет прогресс; последняя изученная колода закрепляется наверху даже из вложенной папки.
2. Ручной флаг 🇺🇸 не меняется автоматически при повторном открытии или редактировании языка.
3. CSV/XLSX со столбцами `word,translation,example` импортирует русские/немецкие символы и показывает пример *курсивом сразу после переворота*; пустые примеры не создают пустой блок.
4. «Импорт колоды» из CSV/XLSX создаёт новую колоду в выбранной папке; «Импорт карточек» добавляет в существующую.
5. Дубликат обнаружен до импорта; «пропустить/обновить/добавить» работают независимо, без скрытой потери истории FSRS.
6. Быстрое редактирование во время повторения сохраняет изменения и оставляет пользователя на той же карточке и не сбрасывает её расписание.
7. Четыре пастельные кнопки показывают **рассчитанные**, а не фиксированные интервалы, создают корректный лог и обновляют due с использованием реального `ts-fsrs`.
8. Для `both`: независимые оценки и due; интервал >=21 дней только в одном направлении **не** засчитывает слово как полностью выученное. При переключении направления история обоих сохраняется.
9. Дневной лимит 80 по умолчанию можно изменить отдельно для колод; повторения сверх лимита продолжают появляться; слово в `both` считается один раз в лимите новых.
10. Streak засчитывается только за реальный ответ. Проверки для полуночи, двух дней подряд, пропущенного дня и смены месяца/года.
11. Перезагрузка браузера, работа офлайн после первого открытия, обновление приложения и восстановление из полной JSON-копии сохраняют колоды, расписания, папки и статистику.
12. Для OneDrive тесты с mock Graph API: офлайн-очередь, токен/сессия истекли, повтор операций без дублей, ETag-конфликт, редактирование на двух устройствах, отсутствие потери ReviewLog, восстановление после сетевой ошибки.
13. Сборка, типизация, тесты и GitHub Pages base-path проходят. Не выдавай тесты с mock за проверку реального OneDrive; отдельно задокументируй необходимость проверки на живом аккаунте.

## 14. Границы первой версии и нерешённые вопросы

**Уже согласовано и обязательно:** папки, редактируемые колоды и карточки, флаги с ручной заменой, импорт CSV/XLSX включая примеры, пометка дубликатов с решением пользователя, FSRS 90%, критерий выученности >=21 день, независимые направления, регулируемый лимит новых слов (дефолт 80), примеры всегда показаны при наличии, пастельные кнопки, streak, локальное офлайн-хранение и цель автоматической синхронизации.

**Не утверждено отдельно — не раздувать объём первой версии:** аудиопроизношение, изображения, избранное, уведомления, полные графики/heatmap, совместные колоды/аккаунты других пользователей, обучение всей папки одной сессией, импорт Anki/Noji/ZIP. Вложенные папки — рекомендуемое техническое допущение; если их реализация слишком затратна, реализуй хотя бы один уровень без блокирования будущей вложенности.

**Резервные копии:** обязательны ручной экспорт/импорт полного JSON, автоматические периодические резервные копии не утверждены. **OneDrive:** подтверждена необходимость автоматической облачной синхронизации; конкретный тип OneDrive-аккаунта пока не указан, поэтому работоспособность авторизации на живом аккаунте требует отдельной настройки и проверки.
